# 翻译工作台自适应尺寸与布局同步设计规格

> 状态：已实施并通过发布验收
> 关联任务：修复翻译窗口放大后顶部大面积空白、操作按钮错位，并加入内容自适应高度
> 影响架构：`docs/architecture/overview.md` 中的智能翻译工作台、主控与会话浮窗

## 1. 背景与问题

翻译工作台当前同时由两层代码修改尺寸：

- `PopupController` 创建、恢复和缩放外层 `NSPanel`；
- `TranslationWorkspaceView` 在内容变化时直接修改自己的 `frame.height`。

当外层面板恢复为较高尺寸、用户手动拉高窗口，或展示动画被内容更新打断时，内部工作台可能仍停留在较小高度。工作台以底部为原点，最终表现为顶部大面积空白，图钉、复制、关闭按钮停在窗口中部，原文和译文卡片只占下半部分。

现有短内容契约还要求 `configure()` 直接把内部 View 缩至约 430 pt，测试因此固化了错误的尺寸职责。本次必须同时修复生产代码和该契约，而不是只在截图对应路径加一个补丁。

## 2. 目标

- 外层面板是实际窗口尺寸的唯一所有者。
- 内部翻译工作台在任何展示、缩放、恢复和动画状态下都铺满 `contentView.bounds`。
- 新翻译根据内容量自动选择合适高度，短内容紧凑、长内容展开。
- 翻译、重新翻译或智能处理完成后，内容显著变长时窗口可以自动增高。
- 用户手动调整窗口后，当前窗口不再被自动尺寸逻辑覆盖。
- 自动调整保持窗口顶部位置稳定，并始终位于当前显示器可见范围内。
- 原文、译文继续使用两个独立滚动区域；窗口不会随正文无限增高。

## 3. 非目标

- 不改变 Azure Translator、Azure OpenAI 或 Azure Speech 的请求协议。
- 不改变智能排版、智能润色的手动触发语义。
- 不改变原文、译文编辑、复制、朗读和最近结果内容。
- 不重新设计翻译工作台的颜色、字体、卡片样式或按钮顺序。
- 不恢复 DeepSeek、Gemini、Anthropic、标准 OpenAI 或 OpenAI Compatible。

## 4. 尺寸所有权

### 4.1 TranslationWorkspaceView

`TranslationWorkspaceView` 只负责：

- 根据当前原文和译文计算推荐内容高度；
- 通过纯值属性或回调向控制器报告推荐高度；
- 在自己的当前 bounds 内布局原文卡片、译文卡片和底栏。

它不得在 `configure()`、`updateTexts()`、`updateReports()`、文本编辑回调或 AI 处理回调中直接修改自己的 `frame`。

`fittingSize.height` 可以返回推荐高度，但推荐高度不等于实际 View 高度。实际高度始终由父容器决定。

### 4.2 PopupController

`PopupController` 是外层面板几何的唯一所有者，负责：

- 初次展示高度；
- 翻译完成后的自动高度调整；
- 当前显示器安全边界；
- 保持顶部锚点；
- 手动缩放优先级；
- 隐藏、恢复、历史切换和展示动画后的尺寸同步。

翻译工作台加入面板后必须保持 `.width` 与 `.height` autoresizing，并在所有关键路径执行防御性同步：

```text
activeBody.frame = paper.bounds
activeBody.autoresizingMask includes width and height
```

该同步至少覆盖初次安装、展示动画结束、`windowDidResize`、`windowDidEndLiveResize`、隐藏恢复、最近结果切换和当前窗口恢复。

## 5. 内容自适应高度

### 5.1 推荐高度

推荐高度使用可单独测试的纯值策略，输入为原文、译文和显示器可用高度。内容需求以两侧较大的一侧为准，综合实际换行数和按约 115 个字符估算的视觉行数：

```text
visualLineDemand = max(actualLineCount, ceil(longestTextCharacterCount / 115))
rawHeight = 430 + max(0, visualLineDemand - 14) * 8
preferredHeight = clamp(rawHeight, 430, 760)
```

高度以 10 pt 为步长向上取整，避免内容轻微变化导致 1–2 pt 抖动。

- 短内容通常为约 430 pt；
- 普通邮件或中等文章在 430–760 pt 之间；
- 长邮件、长文章最高约 760 pt；
- 最终高度不得超过当前显示器 `visibleFrame.height - 24`；
- 若屏幕较小，卡片内部滚动，不突破安全边界。

### 5.2 初次展示

- 新翻译工作台保留用户保存的合理宽度。
- 新翻译的初始高度由当前内容推荐高度决定，不直接继承提问会话或其他窗口保存在共享 `popupSize` 中的高度。
- 最近结果以快照内容重新计算推荐高度，但如果正在恢复同一个隐藏窗口，则优先恢复隐藏前的完整 frame。

### 5.3 翻译与智能处理完成

- 请求进行中不随每个增量或状态文字反复缩放。
- Translator 完整返回后重新计算一次高度。
- 单侧智能排版、单侧智能润色和双侧一键处理成功后重新计算一次高度。
- 如果内容变长且用户尚未手动缩放，窗口平滑增高。
- 如果内容变短且用户尚未手动缩放，只在一次完整操作成功结束后平滑收紧一次。
- 网络、解析或校验失败不改变窗口高度，也不得覆盖已有 Translator 结果。

### 5.4 用户手动调整优先

- 用户通过系统边缘或右下角握把完成一次有效缩放后，将当前窗口标记为 `userResized`。
- `userResized` 为真时，后续翻译、排版、润色和文本编辑只更新内部内容，不再自动改变外层窗口尺寸。
- 内部工作台仍必须持续铺满窗口。
- 关闭当前窗口并开始新的翻译后，重新启用内容自适应。
- 固定窗口只改变自动隐藏语义，不改变尺寸优先级。

## 6. 位置与动画

- 自动增高和缩小时优先保持当前窗口顶部 `maxY` 不变，让窗口主要向下展开或向上收回。
- 如果向下展开会越过当前显示器底部，则在不改变目标高度的前提下整体上移。
- 所有最终 frame 都经过现有显示器夹紧逻辑，不能跨出 `visibleFrame`。
- 展示内容切换动画可以临时采用特殊 autoresizing，但必须有统一的完成清理路径。
- 动画被新展示、窗口恢复或内容更新打断时，当前 active body 仍必须恢复宽高跟随并铺满 paper bounds；过期 body 不得重新成为 active body。
- 自动高度动画不得被误判为用户手动缩放，也不得写入手动尺寸偏好。

## 7. 状态与数据流

```text
内容创建或完整更新
  -> TranslationWorkspaceView 计算推荐高度
  -> PopupController 判断是否为翻译工作台、是否 userResized
  -> 计算屏幕安全目标 frame，并保持顶部锚点
  -> 程序化调整 NSPanel
  -> 同步 active body 到 paper.bounds
  -> 原文/译文卡片在新 bounds 中重新布局
```

手动缩放路径：

```text
用户开始或完成 live resize
  -> 标记 userResized
  -> 当前可恢复窗口快照保留完整 frame；通用偏好只继续保存合理宽度
  -> 不再执行内容驱动的面板高度变化
  -> 每次 resize 仍同步 active body 到 paper.bounds
```

## 8. 失败与边界处理

- `panel`、`contentView` 或 `body` 不存在时，同步函数安全返回。
- 显示器列表在锁屏、休眠切换或显示器热插拔期间不可用时，使用窗口当前 screen 或安全的主屏 fallback，不做数组无防护取值。
- 可用高度小于常规最小值时，优先保证窗口留在屏幕内，并让内部编辑区滚动。
- 动画 completion 对应的 body 已过期时，只清理旧视图，不覆盖当前 active body 的 frame 或 autoresizing。
- 连续快速触发翻译、最近结果切换或隐藏恢复时，最后一次展示状态拥有最终尺寸。

## 9. 测试设计

业务契约测试由全新上下文的独立测试 Agent 先编写并确认当前实现红灯，生产实现随后修复至绿灯。

### 9.1 纯值高度策略

- 短内容推荐约 430 pt。
- 中等内容得到 430–760 pt 之间的高度。
- 长内容推荐约 760 pt。
- 小屏幕受 24 pt 安全边距限制。
- 轻微内容变化不会造成低于 10 pt 的高度抖动。

### 9.2 View 尺寸职责

- `configure()` 只更新推荐高度，不改变调用方传入的实际 frame。
- `updateTexts()`、`updateReports()` 和文本编辑不自行改变实际 frame。
- 任意实际 frame 下，原文卡片、译文卡片和底栏都位于工作台 bounds 内。

### 9.3 面板同步

- 面板从 430 pt 拉到 760 pt 后，body 高度与 paper bounds 一致。
- 面板从 760 pt 缩到 430 pt 后，body 仍完全铺满。
- 顶部操作按钮始终位于工作台右上角，不停留在旧高度。
- 隐藏后恢复、最近结果切换和当前窗口恢复后仍保持一致。
- 内容 crossfade 动画被第二次展示打断后，active body 最终仍具备宽高 autoresizing。

### 9.4 自适应与手动优先

- 短内容完成翻译后保持紧凑。
- 内容由短变长且未手动缩放时自动增高，并保持顶部锚点。
- 完整操作后内容变短且未手动缩放时只收紧一次。
- 用户手动缩放后，后续内容变化不改变面板 frame。
- 程序化自适应不会设置 `userResized`，也不会污染手动尺寸记录。

### 9.5 发布验收

- 现有翻译、智能排版、智能润色、复制、朗读和最近结果契约全部通过。
- `arm64` 与 `x86_64` 类型检查通过。
- Universal `Glint.app` 与 `Glint.dmg` 构建成功。
- 使用 `Glint Self Signed` 签名，签名验证通过。
- 安全替换 `/Applications/Glint.app` 并重新启动。
- 使用完全虚构内容完成隔离 UI smoke，验证短、中、长三种高度以及手动拉伸、隐藏恢复、历史切换。
- 功能分支推送 GitHub，通过 PR 使用 merge commit 合并 `main`，不 squash、不 rebase，并保留功能分支。

## 10. 验收标准

- 无论外层窗口多高，内部工作台都与窗口内容区同高，不出现顶部大面积空白。
- 图钉、复制、关闭按钮始终固定在窗口右上角。
- 短内容打开时紧凑，普通邮件按内容量增高，长内容最高约 760 pt。
- 内容完整更新后可以自动扩缩，但用户手动拉过窗口后当前窗口尺寸保持不变。
- 自动调整保持顶部位置稳定，不越过当前显示器可见边界。
- 原文、译文独立滚动、编辑、复制、朗读和手动 AI 功能不退化。
- Azure Key、邮件正文、剪贴板正文和真实用户内容不进入测试、日志、规格或 Git。
