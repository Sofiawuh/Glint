# 跨应用文本选区兼容层设计

## 1. 背景与已确认问题

Glint 已能在选区右下角显示赤陶色微型入口，但首版主要从系统焦点 Accessibility 元素读取 `AXSelectedText` 、`AXSelectedTextRange` 和 `AXBoundsForRange`。不同应用暴露选区的方式不一致：

- Chrome、企业微信和标准文本应用能返回完整选区范围与边界，当前链路正常。
- Safari、微信和 VS Code 中，选区可能存在于鼠标命中元素、`AXWebArea`、`AXDocument`、编辑器容器或它们的父级，而不在当前焦点元素。
- 某些 WebKit、Electron 或自定义渲染界面只能通过标准复制动作提供文本，不提供可用的 AX 范围或边界。
- 当前剪贴板降级要求必须另有 AX 范围或边界变化证据，因此这些应用即使可以复制选中文本，也会被静默拒绝。

用户已确认交互目标：保留“鼠标真正选中文字后，在选区右下角显示微型入口”；不改为右键菜单或必须按快捷键的流程。

## 2. 目标与成功标准

- Safari、Chrome、微信、企业微信、VS Code、标准文本编辑器和邮件客户端使用同一套通用选区兼容链路，不维护应用名称白名单。
- 鼠标拖选、双击选词和三击选段只要形成新的非空文本选区，就显示现有右下角入口。
- 桌面拖框选文件、点选图标、拖动滚动条、调整列宽/行高、Slider、Splitter、窗口边缘等操作不得触发。
- 不记录或输出选中文本，不泄露 Endpoint、Key 或请求正文。
- 不破坏 Azure Translator、Azure OpenAI v1、截图快捷键、流式会话、图钉和窗口恢复。

## 3. 方案比较与选择

### 方案 A：只扩展 AX 元素搜索

从焦点元素扩展到释放点命中元素及父链，但仍要求完整 AX 证据。优点是误触风险最低；缺点是仍无法覆盖只支持复制、不暴露 AX 选区的界面。

### 方案 B：只要拖动就模拟复制

鼠标释放后无条件发送 `⌘C`，复制到字符串就视为选区。优点是覆盖面大；缺点是会对旧选区、单元格、桌面文件和自定义控件产生误判，不采用。

### 方案 C：多层 AX 搜索 + 受保护的剪贴板降级（采用）

先搜索最可能持有选区的 AX 元素；只有在 AX 信息不足、鼠标手势符合文本选择特征且命中路径不含排除控件时，才允许一次受保护的 `⌘C` 降级。它在通用兼容和误触风险之间取得平衡，不依赖应用白名单。

## 4. 分层选区读取

### 4.1 AX 候选元素搜索

每次鼠标释放后，按以下顺序收集且去重候选元素，不遍历整棵 Accessibility 树：

1. 系统焦点元素。
2. 鼠标释放点命中元素。
3. 上述两者各自的有限父级链，优先检查 `AXTextArea`、`AXTextField`、`AXStaticText`、`AXWebArea`、`AXDocument`、`AXCell` 和 `AXLink`。

每个候选元素读取：

- `AXSelectedText`。
- `AXSelectedTextRange`。
- `AXBoundsForRange`。
- 元素 role/subrole、元素身份和前台应用身份。

候选排序优先级为：非空文本 + 非零范围 + 可用边界，其次是非空文本 + 范围，最后是仅有非空文本。鼠标选区可以在缺少边界时使用本次释放点定位；键盘选区仍不猜测锚点。

### 4.2 控件角色预过滤

按下点或释放点的任一角色祖先属于下列类型时，立即结束读取，不进入剪贴板降级：

- ScrollBar / ScrollAreaThumb。
- Slider / Splitter / Incrementor。
- ColumnHeader / RowHeader / Ruler。
- ResizeHandle / Resizer / GrowArea / WindowResizeHandle。
- ToolbarDragArea 和其他明确的拖动、调整控件。

### 4.3 受保护的剪贴板降级

只有同时满足以下条件才允许模拟 `⌘C`：

- AX 候选搜索没有返回可接受快照。
- 命中角色链不含排除控件。
- 鼠标手势是有明确位移的拖选，或本次 `clickCount >= 2` 的双击/三击选择。零位移单击不使用无 AX 证据的剪贴板降级。
- 复制后剪贴板确实产生新变更，且存在去除首尾空白后的非空纯文本。
- 剪贴板不包含文件 URL、文件列表、图像等表明本次是桌面文件或非文本对象的类型。

降级成功后生成 clipboard-only `SelectionSnapshot`：

- 文本来自本次复制结果。
- 来源应用来自当前前台应用。
- 焦点元素身份可用时保留，但不将它作为必需条件。
- 没有 AX 边界时，入口锚定本次鼠标释放点。
- 用不可逆文本指纹区分同一降级选区，日志不得输出原文或指纹。

复制完成后必须恢复用户原剪贴板的全部类型和数据，无论成功、失败或读取被代际令牌作废。

## 5. 选区稳定性与消失规则

- AX 快照继续使用文本、应用、元素、范围指纹和边界判断是否为新选区。
- clipboard-only 快照使用文本指纹 + 来源应用判断是否为同一选区，相同选区不因无关鼠标释放重复弹出。
- clipboard-only 入口遇到新鼠标按下、Escape、普通用户按键或前台应用切换时直接失效；不为了保留入口而再次自动复制。
- 所有 AX 读取、剪贴板复制和延迟回调延续使用代际令牌，新手势、键盘输入或前台应用切换后，旧结果不得复活入口。

## 6. 交互与定位

- 保留现有 10×10 pt 赤陶色圆角方块、22×22 pt 透明命中区、180 ms 悬停展开和 400 ms 离开收回。
- 有可靠 AX 边界时继续附着于选区联合边界右下角。
- 只有 clipboard-only 读取没有边界时，才使用本次鼠标释放点作为右下角定位兜底。
- 现有“翻译 / 提问”动作、窗口恢复与 Azure 请求链路不变。

## 7. 测试与验收

### 7.1 独立黑盒测试

按仓库 TDD 约束，先由全新独立测试代理人编写并运行红灯契约，覆盖：

- 焦点元素无选区、父级 WebArea/Document 有选区时，选择最佳候选快照。
- 命中元素有选区、焦点元素无选区时仍能接受。
- 多个候选中优先选择具有非零范围和边界的结果。
- 未知角色上的真实拖选或双击允许受保护复制降级。
- 零位移单击、无剪贴板新变更、空白文本和文件/图像类型都被拒绝。
- 滚动条、滑块、分隔条、列头和调整柄绝不进入复制降级。
- clipboard-only 快照使用释放点定位，且不会在普通按键后复活。
- 剪贴板所有原始类型与数据在成功、失败和取消路径均恢复。

## 8. 安全、隐私与非目标

- 不针对 Safari、微信、VS Code 等应用名写白名单或特殊分支。
- 不将选中文本、剪贴板内容、聊天内容、Endpoint、Key 或请求正文写入日志。
- 不保留自动复制所得文本；只在用户点击“翻译”或“提问”后把当前快照交给既有 Azure 链路。
- 不往第三方应用右键菜单注入项目，不替换原生右键菜单。
- 不对完全禁止复制且不暴露任何 AX 选区的界面强制取词；这类界面仍宁可不显示，不得猜测或读取非选中内容。
