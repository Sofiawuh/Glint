# Glint 最近结果历史设计

日期：2026-11-24  
状态：已确认，待实施

## 1. 问题与目标

当前菜单“显示上次窗口”只能恢复因外部点击而进入 `hiddenRestorable` 的同一个窗口，不是最近翻译或提问的历史。菜单名称与实际行为不一致，失败时又没有可见反馈。

本次将菜单扩展为当前 Glint 进程内的“最近结果”：

- 最多保留最近 10 条已完成的文字翻译或文字提问结果；
- 鼠标悬停“最近结果”子菜单即展开列表；
- 点击任意一条后，使用唯一的内容窗口重建该结果；
- 历史窗口只读，可复制、钉住和关闭，不能继续追问；
- 历史只存在于当前进程内存，退出或重启 Glint 后自动清空。

## 2. 范围

首版只记录由文字命令快捷键产生的已完成结果：

- 翻译：选中文本和最终译文；
- 提问：选中文本、用户问题和已完成的回答内容。同一次多轮追问作为一条记录，在当前活跃会话内完成新回答时更新该记录，不额外占用一个名额。

以下内容不进入历史：

- “翻译 / 提问”快捷操作条；
- “翻译中…”、流式生成中的不完整内容、连接失败和错误提示；
- 尚未提交的提问草稿；
- 截图提问、图像、Base64 和其他二进制内容；
- Azure Key、Endpoint、Region、部署名称或任何凭据。

## 3. 菜单交互

菜单栏结构调整为：

```text
显示当前窗口
最近结果 ›
    12:20  提问 · Azure 白名单为什么失败…
    12:16  翻译 · FAILED_PRECONDITION…
    12:08  提问 · 这个日志怎么看…
    ────────────
    清空最近结果
设置…
退出
```

- 原“显示上次窗口”重命名为“显示当前窗口”，继续用于恢复已隐藏的当前提问草稿或当前内容窗，避免既有恢复能力回归；
- “最近结果”始终显示；列表为空时子菜单显示置灰的“暂无最近结果”；
- 列表按完成或最后更新时间倒序排列；
- 菜单标题包含 `HH:mm`、“翻译 / 提问”类型和单行摘要，过长时截断并加省略号；
- 点击某条记录会关闭当前已显示的内容窗，并在鼠标所在显示器上打开该历史的只读窗口；
- 切换到历史不会丢弃当前空闲会话或未发送草稿；“显示当前窗口”可切回并恢复原内容、草稿和窗口状态。开始新的翻译、提问或截图任务时，才按现有规则替换当前会话；
- 当前翻译或回答正在请求时，历史记录保持可见但暂不可切换，防止隐式取消在途请求；
- “清空最近结果”立即删除全部内存历史。如果正在显示历史窗，同时关闭该只读窗；不影响正在进行的新任务。

## 4. 数据与内存边界

新增独立的纯 Swift 内存模块，与 `NSPanel` 和 Azure 请求解耦：

- `RecentResultEntry`：唯一 ID、类型、完成时间、菜单摘要和只读内容快照；
- `RecentResultStore`：按时间倒序保存、同 ID 更新、超限淘汰、查找和清空；
- 翻译快照只保存源文摘要与最终译文；
- 提问快照保存选中文本摘要与已完成的问答 transcript，不保存可继续发送的 Azure messages；
- 不保存 `NSPanel`、`NSView`、`NSTextView`、属性字符串、网络任务、Timer、图片或剪贴板对象；
- 任何时候最多只有一个真实内容窗。历史列表不对应 10 个隐藏窗口。

内存限制同时使用两个门槛：

- 最多 10 条；
- 纯文本内容估算总量最多 10 MB。

新条目加入后如任一门槛超限，按从旧到新的顺序淘汰，直到同时满足两个门槛。单条结果如已超过总内存预算，不进入历史，但仍正常显示当次结果。

## 5. 只读窗口

历史结果不重用活跃会话状态，只根据快照重建可视内容：

- 翻译历史按当前 Markdown 结果窗样式展示译文；
- 提问历史展示选中文本摘要和已完成的问答 transcript；
- 保留复制、图钉、关闭和窗口缩放；
- 不创建输入框、发送按钮、网络请求或可追问会话；
- 点击 `×`、按 Escape 或外部点击只改变该历史窗的可见状态，不删除历史记录；
- 重新点击同一条历史时再次重建或将已隐藏的同一窗带到最前。

## 6. 生命周期与并发

- 翻译只在获得最终成功结果后新增记录；
- 提问只在一轮 assistant 流式回答正常完成后新增或更新记录；
- 取消、超时、错误或被新任务替换的不完整回答不写入历史；
- 记录组装和菜单更新仅在主线程执行；流式请求仍按现有 generation 机制拒绝过期回调；
- 显示历史前如有可见的当前窗，使用现有明确关闭路径释放 UI 引用，但不回写或删除已完成历史；
- 当前空闲会话的数据模型与未发送草稿独立于历史快照保留；历史窗关闭后，菜单仍可恢复当前会话。历史浏览本身不触发当前会话的网络请求、取消或状态迁移；
- 进程退出时不执行序列化，历史随内存释放。

## 7. 错误处理

- 历史 ID 在菜单点击前已被清空或淘汰时，安全刷新菜单并不打开窗口；
- 历史窗构建失败时不影响原历史列表，显示简短本地错误提示，不发起 Azure 请求；
- 历史菜单不记录正文，日志只允许记录条目 ID、类型、条数和状态；
- 清空历史后必须释放条目内的所有字符串引用。

## 8. 测试与验收

按 TDD 先由全新测试上下文增加纯契约测试并确认红灯，至少覆盖：

- 翻译和已完成提问进入历史，加载、错误和未发送草稿不进入；
- 最多 10 条且超过纯文本预算时淘汰最旧记录；
- 同一问答会话更新原记录而不重复新增；
- 菜单按时间倒序、摘要截断、空状态、清空和历史 ID 路由；
- 点击历史只重建单个只读窗，不创建输入框或 Azure 请求；
- 原“显示当前窗口”的隐藏恢复能力不回归；
- `×`、Escape、外部点击和清空历史的生命周期与纪录保留语义；
- 日志不出现历史正文、选中文本、问题、回答或凭据。

回归要求：

- 现有快捷键、配置迁移、按需取词、剪贴板保护、Azure、面板、几何、Markdown 和浮窗测试全部通过；
- `arm64-apple-macos12.0` 与 `x86_64-apple-macos12.0` 全应用类型检查通过；
- 隔离 Home 的菜单与历史窗 UI smoke test 通过；
- 使用 `Glint Self Signed` 构建、安全替换 `/Applications/Glint.app`、验签并重启；
- 独立只读复审达到 `APPROVE / P0=0 / P1=0 / P2=0` 后才提交功能代码。

## 9. 非目标

- 不持久化、同步、搜索、分组、编辑或导出历史；
- 不从历史窗继续追问、重试或重新发起网络请求；
- 不保留 10 个真实窗口或 UI 树；
- 不保存截图、图片、Base64 或截图问答；
- 不改动文字命令、截图快捷键、Azure 配置和既有网络协议。
