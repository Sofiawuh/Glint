# 文本选区微型悬停入口设计

## 1. 背景与问题

Glint 过去把“鼠标左键拖动距离超过阈值”视为划词，并在鼠标释放后读取选中文字、直接显示完整的“翻译 / 提问”胶囊。这种触发方式存在三个问题：

- 交互过于主动。用户只是选中文字时，完整胶囊立即出现，容易遮挡阅读内容。
- 拖动横向滚动条、表格列宽、滑块或其他控件时，同样可能超过距离阈值；如果前台应用仍保留文本或单元格内容，Glint 会误取词并弹窗。
- 双击选词、三击选句或选段、`Shift + 方向键` 扩选和 `⌘A` 全选通常没有明显鼠标拖动距离，因而不会触发入口。

用户已批准方案 A：不判断用户通过何种方式选中，只要形成新的、非空的真实文本选区，就在选区右下角直角上显示一个凸出式方块把手；鼠标主动悬停后才展开“翻译 / 提问”。旧的“拖动结束后直接显示完整胶囊”和独立星芒图标行为均被替换，不增加新旧模式开关。

## 2. 目标

- 只有确认产生了新的有效文本选区时才显示 Glint 入口，覆盖鼠标拖选、双击、三击、键盘扩选和全选。
- 入口锚定在真实选区右下角，而不是简单跟随鼠标释放点。
- 默认仅显示与选区直角连成一体的微型方块把手，不抢焦点、不改变原应用选区。
- 用户主动悬停后才展开“翻译 / 提问”，避免选完文字立刻出现大胶囊。
- 横向滚动条、列宽、滑块、分隔条和其他控件拖动不得触发入口。
- 继续复用现有翻译、提问、流式会话、图钉、隐藏恢复和 Azure 请求链路。

## 3. 用户交互

### 3.1 文本选中

1. 用户在任意应用中形成新的文本选择，来源可以是鼠标拖选、双击选词、三击选句或选段、`Shift + 方向键` 扩选、`⌘A` 全选或其他会改变文本选区的标准操作。
2. Glint 在鼠标释放或键盘操作结束后短延迟异步验证选区，不阻塞全局事件 Tap，也不持续轮询。
3. 验证成功后，在选区右下角直角处显示一个向外凸出的微型方块把手。
4. 此时不显示“翻译 / 提问”，也不激活 Glint 或让原应用失去焦点。

微型入口采用与 Glint 现有视觉一致的赤陶色，但不再表现为独立图标：

- 可见尺寸约 `10 × 10 pt`，命中区域扩展到约 `22 × 22 pt`。
- 使用 `ClaudeTheme.terracotta` 的实心小方块，约 `2–3 pt` 轻微圆角，带克制的浅色描边和外投影。
- 完全移除内部白色四角星芒，不绘制额外图案或文字。
- 默认让方块中心与选区右下角直角重合，使其一半覆盖边角、一半向外凸出，视觉上像选区边框自然长出的把手，而不是与选区分离的按钮。
- 多行、整段或整篇文章使用 AX 选区联合边界的右下角；入口不得为了屏幕夹紧而脱离该直角，屏幕空间不足时优先改变展开胶囊方向。

### 3.2 主动悬停展开

- 鼠标明确进入微型入口后，等待约 `180 ms` 再展开，过滤快速掠过。
- 展开方向优先向左或向上，使胶囊远离选区正文并保持方块把手附着在原直角；空间不足时由几何层选择其他可见方向。
- 展开内容继续使用现有两个动作：“翻译”和“提问”。
- 微型入口与展开胶囊之间建立连续命中区域，鼠标从入口移动到按钮时不会因短暂跨越间隙而收起。
- 鼠标离开入口和展开胶囊约 `400 ms` 后，胶囊收回为微型入口；重新移入仍可展开。

入口刚出现时不得因为鼠标仍停留在选择终点而自动展开。入口进入“待激活”状态，只有鼠标在入口出现后发生明确移动，并从入口外进入命中区域，才开始 `180 ms` 悬停计时。这样标准的顺向拖选不会退化为旧的自动弹出行为。

### 3.3 消失规则

微型入口保持可用，直到发生以下任一路径：

- 用户点击“翻译”或“提问”。
- 用户在入口和胶囊之外再次按下鼠标。
- 用户按下 Escape。
- 新的有效文本选区替换当前选区。
- 前台应用或焦点元素变化，且原选区已不可验证。
- Glint 的已有内容窗口处于钉住状态并拒绝新选区。

不使用短暂的固定自动消失倒计时，避免用户选中文字后稍作阅读就无法再使用入口；小入口本身足够克制，由下一次明确交互负责清除。

## 4. 选区检测与误触发过滤

### 4.1 不再以拖动距离或鼠标手势作为成功条件

拖动距离不再参与是否读取选区或是否显示入口的决定。最终是否呈现入口只由结构化的选区结果及其相对上一稳定快照的变化决定。鼠标移动距离为零时，只要双击或三击形成了新选区，也必须触发。

事件入口包括：

- 每次鼠标左键释放，包括普通拖选、双击和三击后的释放。
- 可能改变文本选区的键盘操作结束，包括 `Shift + 方向键`、`Shift + Home/End`、`Shift + PageUp/PageDown`、`⌘A` 等。
- 普通用户按键仍会作废在途旧读取，并在短延迟后复验当前入口；选区未变化时保留，选区确实变化或无法验证时关闭。
- Glint 内部模拟 `⌘C` 使用专用事件来源标记，不得被当成用户键盘操作，也不得作废自身剪贴板降级读取。

事件结束后短延迟读取新的选区快照。只有满足以下条件才接受：

- 文本去除首尾空白后非空。
- 选区范围长度大于零，或可靠的文本选区证据表明本次选择成立。
- 相比上一份稳定观察或已展示快照，选区范围、文本指纹或选区边界发生了有效变化；同一旧选区不得因无关点击或滚动重复触发。
- 鼠标命中元素及其祖先链不属于被排除的控件角色。

对于信息不足的应用采用“宁可不显示，也不误弹”的原则。

### 4.2 控件拖动排除

鼠标交互在按下与释放时通过 Accessibility 命中测试读取光标下元素，并沿父元素检查角色。以下类型默认排除：

- 滚动条与滚动条拇指。
- Slider、Splitter、Incrementor。
- 表格列宽/行高调整柄、列头、行头与标尺。
- 工具栏拖动区、窗口调整区和其他明确的可拖动控件。

Excel、Azure 日志结果表格和浏览器中的横向滚动条即使拖动距离很长，也不得进入取词或模拟复制流程。

### 4.3 AX 优先与剪贴板降级

首选 Accessibility：

1. 从焦点元素读取 `kAXSelectedTextAttribute`。
2. 读取 `kAXSelectedTextRangeAttribute`。
3. 使用 `kAXBoundsForRangeParameterizedAttribute` 获取真实选区边界。

AX 返回有效文本和边界时，直接生成包含文本、范围指纹和选区矩形的 `SelectionSnapshot`。

当应用只能返回文本、不能返回边界时，可以使用鼠标释放点作为定位兜底，但仍必须通过选区变化和控件角色验证。

只有当前元素属于可接受的文本类角色、AX 无法读取选中文字且不在排除控件内时，才允许使用现有模拟 `⌘C` 的剪贴板降级。降级路径继续完整快照和恢复剪贴板；用于证明选区变化的 AX 范围指纹和边界必须保留进最终 `SelectionSnapshot`，供后续键盘复验使用；纯控件拖动不得发送 `⌘C`。

## 5. 坐标与定位

新增纯数据结果：

```swift
struct SelectionSnapshot {
    let text: String
    let sourceApplication: String?
    let focusedElementIdentity: String?
    let rangeFingerprint: String?
    let boundsInQuartz: CGRect?
    let releasePointInQuartz: CGPoint
}
```

选区矩形从 Quartz 左上原点转换为 AppKit 左下原点时，继续遵守现有多屏约束，以原点 `(0, 0)` 所在主屏高度为翻转基准。几何层接收选区矩形、入口尺寸、展开尺寸和屏幕 `visibleFrame`，输出：

- 附着于选区右下角的可见方块矩形及扩大后的透明命中区域。
- 展开胶囊矩形。
- 展开方向。
- 连续悬停命中区域。

多行文本使用 AX 返回的选区联合边界，方块把手附着于联合边界右下角。AX 无边界且来源为鼠标选择时，才使用释放点；键盘选区如果没有可靠边界则不猜测位置。几何计算必须覆盖主屏、负坐标外接屏、左右边缘、底部 Dock、反向拖选和整页大范围选区。屏幕边缘场景优先翻转或移动展开胶囊；若默认居中会裁掉方块，则让方块向可视区内侧绕同一角点偏置，但至少一条边仍接触该角点，不产生可见间距，也不跳到选区左下角。

## 6. 窗口与焦点行为

新增 `SelectionEntryController`，持有一个专用的不激活 `NSPanel`；微型入口和展开胶囊在同一个面板内切换：

- 使用 non-activating 行为展示，不调用 `NSApp.activate` 或 `makeKeyAndOrderFront`。
- 面板不成为 key window，不改变前台应用焦点，不清除原文本选区。
- 展开与收起只改变该面板的窗口帧和内容，不创建多个相互竞争的入口窗口。
- 点击具体动作后，`SelectionEntryController` 先关闭入口面板，再把文本和动作交给现有 `PopupController`；“提问”可以按现有行为激活输入窗口，“翻译”继续显示结果窗。

现有完整快捷胶囊的按钮组件、动作方法和视觉样式可以复用，但“选择检测”和“微型入口生命周期”从 `PopupController` 中拆为清晰边界，避免继续把全局输入、AX 读取、悬停定时器和会话窗口状态耦合在一个类中。

## 7. 状态模型

新增可独立测试的 `SelectionEntryLifecycle`：

- `hidden`：没有入口。
- `marker(snapshot)`：附着式方块把手可见，等待用户主动移入。
- `hoverPending(snapshot)`：鼠标已明确进入，等待 `180 ms`。
- `expanded(snapshot)`：显示“翻译 / 提问”。
- `collapsePending(snapshot)`：鼠标离开，等待 `400 ms`；期间重新进入则取消收起。

关键规则：

- 创建 `marker` 时不会直接进入 `hoverPending`。
- 未发生入口出现后的明确鼠标移动，不允许展开。
- 新有效选区替换当前快照并在新的右下角重新显示 `marker`；旧的异步读取或键盘复验结果不得关闭新入口。
- 新的无效拖动不覆盖当前有效入口，但新的外部鼠标按下会按消失规则关闭旧入口。
- 钉住的展开内容窗继续忽略新选区；微型入口不出现。
- 翻译或提问动作提交后立即隐藏入口，并把快照文本交给现有动作链路。

所有定时器使用代际令牌或可取消任务，旧选区的延迟回调不得展开或关闭新选区入口。

## 8. 错误与降级

- AX 无权限：沿用现有权限提示，不显示错误弹窗。
- AX 文本为空、范围长度为零或角色被排除：静默忽略。
- AX 有文本但无边界：鼠标选择可使用本次释放点定位；键盘选择因没有可信锚点而静默忽略，不复用旧鼠标位置。
- 剪贴板降级失败：完整恢复剪贴板并静默忽略。
- 多屏坐标无法映射到有效屏幕：使用释放点所在屏幕并夹紧可视区。
- 悬停或面板动画被新选择打断：取消旧动画和定时器，以最新快照为准。

日志只记录判定路径、AX 角色、是否取得范围/边界和几何结果，不记录完整选中文字、Azure Endpoint、Key 或请求正文。

## 9. 测试与验收

测试必须由全新独立测试代理先建立黑盒契约并确认红灯，至少覆盖：

1. 鼠标拖选、双击选词、三击选句或选段都能在无拖动距离门槛的情况下接受新的非空文本范围。
2. `Shift + 方向键`、键盘扩选和 `⌘A` 形成新选区时生成入口请求。
3. 普通点击、空文本和零长度范围不显示入口。
4. 未变化的旧选区不因横向拖动、滚动或无关点击重复触发。
5. AXScrollBar、AXSlider、AXSplitter、列宽调整柄及其子元素拖动被排除。
6. 排除控件路径不会调用剪贴板复制降级。
7. AX 文本和范围边界可用时不调用剪贴板降级。
8. 剪贴板降级保留用于准入的范围指纹和边界，普通按键后相同选区可继续通过复验。
9. AX 有文本无边界时，鼠标选择可使用释放点；键盘选择不得猜测位置。
10. 方块把手中心附着于选区右下角，无额外间距、无星芒图案，视觉尺寸约 `10 × 10 pt`，透明命中区域约 `22 × 22 pt`。
11. 微型入口初次出现时，即使鼠标位于附近也不会自动展开。
12. 入口出现后明确移入并持续 `180 ms` 才展开。
13. 少于 `180 ms` 的快速掠过不展开。
14. 展开后离开少于 `400 ms` 再返回不会收起。
15. 持续离开超过 `400 ms` 后收回为微型入口。
16. 鼠标从入口移动到按钮的连续命中区域不会触发收起。
17. 点击外部、Escape、选区失效和新选区会正确隐藏或替换入口。
18. 旧的异步读取或键盘复验结果不能隐藏后来出现的新入口。
19. 点击“翻译”或“提问”只提交一次当前快照，并清理入口状态。
20. 入口和胶囊展示不激活 Glint、不清除原应用选区。
21. 选区右下角、屏幕右边缘、底部边缘、负坐标外接屏、反向拖选和整页选区定位正确。
22. 钉住内容窗时新选区不显示入口。
23. 现有 Popup、快捷键、Azure、窗口几何和 Markdown 测试继续通过。

UI 烟测至少展示两个状态并生成快照：

- 选区右下角直角上凸出的赤陶色方块把手。
- 悬停展开后的“翻译 / 提问”胶囊。

手工验收覆盖：

- Safari 或 Chrome 网页文字。
- TextEdit、邮件或常规 AppKit 文本。
- Excel 单元格内文字选择与横向滚动条拖动。
- Azure Portal 日志结果表格横向滚动、列宽调整与页面文字选择。
- 多屏、屏幕边缘和反向选择。

最终版本继续使用 `Glint Self Signed` 构建 Universal App，替换 `/Applications/Glint.app`，验证签名、辅助功能授权、事件 Tap、入口悬停行为以及现有截图快捷键。

## 11. 非目标

- 不注入或修改第三方应用的原生右键菜单。
- 不绘制完整的选区边框或覆盖层。
- 不对截图快捷键、Azure 协议、模型配置和流式回答链路做功能改造。
- 不增加“旧自动胶囊 / 新悬停入口”的设置开关。
- 不依赖应用名称白名单解决误触发；以选区证据和 AX 控件角色为准。
- 不承诺在完全不暴露 Accessibility 文本、范围且禁止复制的应用中强行取词；此类应用宁可不显示入口。
