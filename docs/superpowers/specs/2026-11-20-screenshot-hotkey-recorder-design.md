# 自定义截图快捷键录制设计

## 1. 背景与问题

Glint 当前把截图快捷键固定为 `⌃⌥E`：`AppDelegate` 启动时直接用 Carbon 注册 `kVK_ANSI_E + controlKey + optionKey`，基础设置页只显示一段静态说明。用户无法避开与系统或其他应用的快捷键冲突，也无法按个人习惯修改组合键。

本次改动在基础设置页增加原生快捷键录制控件。用户点击控件并直接按下新的组合键；注册成功后立即生效并持久化，重启 Glint 后继续使用。

## 2. 目标

- 默认快捷键继续为 `⌃⌥E`，现有用户升级后行为不变。
- 用户可在“设置 → 基础”中直接录制任意受支持的组合键。
- 新快捷键只有在系统级注册成功后才替换旧快捷键并写入配置。
- 注册失败、配置保存失败或录制取消时，旧快捷键继续有效。
- 旧版 `config.json` 自动补齐默认快捷键，不丢失 Azure Translator 或 Azure OpenAI 配置。
- 快捷键显示采用 macOS 常见符号，例如 `⇧⌘S`、`⌃⌥E`。

## 3. 交互设计

### 3.1 基础设置页

现有“快捷键”静态说明替换为一行紧凑设置：

- 左侧保持“快捷键”标签。
- 右侧显示可点击的原生录制控件，默认内容为 `⌃⌥E`。
- 控件旁保留简短说明：“框选截图，划词后可直接翻译或提问。”
- 控件使用当前 AppKit 设置页的字号、圆角、焦点环和间距，不引入新的设置卡片或独立弹窗。

### 3.2 录制流程

1. 用户点击录制控件，控件进入录制状态并显示“请按新的快捷键…”。
2. 控件获取键盘焦点，捕获下一次完整的 `keyDown`。
3. 合法组合键先交给运行时注册流程验证；非法输入显示行内提示并保持录制状态，继续等待下一次按键。
4. 注册与配置保存均成功后，控件显示新组合键并结束录制；新快捷键立即可用。
5. 控件失去焦点、用户按 Escape 或窗口关闭时，取消本次录制并恢复显示当前有效快捷键。

录制状态中的特殊按键：

- `Escape`：无论是否同时按下修饰键，都取消录制，不修改当前快捷键；Escape 不可设为截图键。
- `Forward Delete` 或 `Backspace`：无论是否同时按下修饰键，都申请恢复默认快捷键 `⌃⌥E`；二者不可设为截图键，默认键同样必须经过注册和保存流程。
- 单独按修饰键：继续等待，不结束录制，也不显示错误。

### 3.3 输入规则

一个可保存的快捷键必须同时包含：

- 至少一个修饰键：Command、Control、Option 或 Shift。
- 一个非修饰键。

拒绝没有修饰键的普通按键，避免 Glint 吞掉日常输入；拒绝只有修饰键的组合。非法普通按键显示行内错误后继续录制。录制支持字母、数字、常用标点、方向键、功能键、Space、Return 和 Tab 等可由 Carbon 注册的物理按键；Escape、Forward Delete 和 Backspace 保留给录制控制，不作为可分配键。

配置保存虚拟键码与标准化修饰键，不保存本地化展示字符串。展示层根据当前键盘布局将普通键转换为可读字符，并为方向键、功能键、Space、Return、Tab 等特殊键使用稳定名称或符号。用户切换键盘布局后，快捷键仍绑定同一个物理键码，但界面按当前布局重新显示。

## 4. 数据模型与配置迁移

新增独立值类型 `ScreenshotHotKey`，职责仅包括：

- `keyCode: UInt32`。
- 标准化后的 Carbon 修饰键位图。
- 默认值 `⌃⌥E`。
- 组合键合法性验证。
- 面向设置页和说明文字的符号化显示；修饰键按 macOS 菜单惯例统一显示为 `⌃⌥⇧⌘` 后接普通键。

`AppConfig` 增加 `screenshotHotKey` 字段。由于 Swift 合成的 `Codable` 不会因为属性有默认值就自动容忍 JSON 缺失字段，`AppConfig` 必须显式实现向后兼容解码：

- `translator` 和 `azureOpenAI` 继续按现有格式解码。
- `screenshotHotKey` 使用 `decodeIfPresent`；字段缺失时采用 `ScreenshotHotKey.default`。
- 编码时写入三项完整配置。

旧配置缺少快捷键字段属于正常迁移，不得触发 `config.pre-azure-backup.json` 恢复路径，也不得重置或覆盖现有 Azure 字段。只有整个配置文件确实无法解码时，才继续使用现有备份与默认恢复行为。

## 5. 运行时注册与事务边界

### 5.1 HotKey 生命周期

现有 `HotKey` 增加显式 `invalidate()`，负责：

- 调用 `UnregisterEventHotKey` 注销自己的 `EventHotKeyRef`。
- 从静态 action 表移除对应 ID，避免闭包残留。
- 将注销设计为幂等操作。
- 在 `deinit` 中执行防御性的 best-effort 注销，但不把它作为正常生命周期保证。

`invalidate()` 必须返回或抛出可观察的 Carbon 状态。只有 `UnregisterEventHotKey` 成功后，才清空 `EventHotKeyRef` 并删除 action；失败时实例保持逻辑有效，不能制造仍占用组合键但没有 action 的僵尸注册。Carbon 事件处理器仍只安装一次。热键实例只负责自己的注册引用、启用状态和 action 生命周期。

事件处理器和热键的创建顺序必须为：

1. 调用 `InstallEventHandler` 并检查 `OSStatus`；只有成功时才能把静态 `handlerInstalled` 标记为 `true`。
2. 事件处理器安装失败时，整个热键创建失败，不插入 action，也不尝试报告注册成功。
3. 处理器可用后，将实例 action 写入按 ID 索引的 action 表。
4. 调用 `RegisterEventHotKey`；注册失败时立即删除刚写入的 action 并返回失败。

所有成功注册的活动或候选实例必须由 `AppDelegate` 的热键状态持有者强引用，直到显式 `invalidate()` 成功。若注销失败，持有者继续保留该实例以维持 action 与 Carbon 注册的一致性并允许后续清理；不能依赖对象进入 `deinit` 后继续重试。`deinit` 只负责进程正常释放路径中的防御性尝试，注销失败仍由进程退出后的系统清理兜底。

`HotKey` 支持“已注册但未激活”状态：Carbon 已占用候选组合键，但事件回调被门控，不会执行截图动作。只有整个配置切换事务提交后才启用候选 action。

### 5.2 录制态事件桥接

开始录制时，`SettingsController` 通过 `AppDelegate` 建立一个进程内录制会话。当前有效的 Carbon 热键保持注册，但其回调临时改为：

- 将当前 `ScreenshotHotKey` 作为录制结果回填给录制控件。
- 不调用 `onScreenshotExplain()`，不启动截图，也不让设置窗口失焦。

因此用户在录制器中按下当前快捷键时，可以到达“相同值、成功无操作”的路径，而不会意外框选截图。其他未被当前 Carbon 注册占用的组合键仍由录制控件的 `keyDown` 捕获。

录制结束的所有路径——应用成功、应用失败、Escape、Delete/Backspace 完成、控件失焦和设置窗口关闭——都必须关闭录制会话并恢复当前热键的正常截图回调。录制会话只改变事件路由，不注销当前热键，也不修改配置。

### 5.3 启动注册

`AppDelegate` 加载 `AppConfig` 后，使用持久化的 `screenshotHotKey` 注册截图动作。若已保存的组合键因系统环境变化而注册失败：

1. 记录不含凭据的错误状态。
2. 尝试注册默认 `⌃⌥E`，保证截图入口尽量可用。
3. 只有默认键成功注册时才把配置修正为默认值；保存失败不影响本次运行中的默认热键。
4. 若默认键也注册失败，应用继续启动，并在设置页显示可理解的错误，允许用户录制其他组合键。

### 5.4 设置页即时应用

`AppDelegate` 提供单一事务入口，例如 `applyScreenshotHotKey(_:)`，设置控制器不直接操作 Carbon 或配置文件。

处理顺序：

1. 标准化并验证候选组合键。
2. 若候选值与当前有效值相同，作为成功的无操作返回。
3. 保持旧 `HotKey` 实例仍然有效，先创建“已注册但未激活”的候选 `HotKey`；候选此时不能执行截图动作。
4. 候选注册失败时释放候选，保留旧实例和旧配置，向设置页返回“快捷键可能已被占用”。
5. 候选注册成功后，将内存配置改为新值并原子写入 `config.json`。
6. 配置保存失败时注销候选实例，恢复内存配置；旧实例始终没有被注销。候选清理失败时进入下述降级状态。
7. 配置保存成功后，尝试注销旧实例。注销成功后才启用候选 action，并把候选实例设为当前实例。
8. 旧实例注销失败时，候选保持未激活。配置回写旧值与候选注销是两个都必须尝试、分别记录结果的补偿步骤；配置回写失败不能跳过候选注销。旧实例继续作为唯一可执行截图动作的热键。

该顺序保证候选值不会在配置提交前提前执行截图，也保证常规失败不会让 Glint 丢失原本可用的截图快捷键。运行时注册、旧注册注销和配置落盘只有全部成功后才对用户表现为“修改完成”。没有当前热键的启动降级状态也使用同一入口，只是旧实例为空。

如果 Carbon 在回滚时连候选注销也失败，候选保持“已注册但未激活”并由状态持有者继续强引用，旧热键继续工作；应用阻止继续创建更多候选，设置页提示“快捷键切换未完成，请重新启动 Glint 后再试”。进程退出后 macOS 会释放该临时注册。该降级路径不能静默删除候选 action 或把候选激活为第二个截图快捷键。

如果旧实例注销失败后的配置回写也失败，运行时仍保留旧热键，并继续独立尝试注销未激活候选：

- 候选注销成功：本进程只剩旧热键可执行，但磁盘仍是候选配置；阻止继续修改并提示“当前仍使用原快捷键；配置恢复失败，重新启动后将再次尝试保存的快捷键”。
- 候选注销也失败：强引用并保持候选未激活；本进程仍只有旧热键执行截图，磁盘仍是候选配置；阻止继续修改并提示必须重启。

两种路径都分别记录旧键注销、配置回写和候选注销状态，不能报告修改成功。重新启动后进程级 Carbon 注册全部释放，Glint 按磁盘中的候选配置重新执行正常的启动注册与默认键回退规则。

每个候选实例必须使用不会与当前活动实例冲突的 Carbon 热键 ID；切换成功后可以回收旧 ID，或使用单调递增且进程内唯一的 ID。

## 6. 组件边界

### `ScreenshotHotKey`

纯值与规则层，不依赖设置窗口或 `AppDelegate`。提供默认值、标准化、验证、Codable 和显示文本，便于独立协议测试。

### `HotKeyRecorderControl`

原生 `NSControl`，只负责焦点、录制状态、键盘事件和显示。通过回调提交候选值，不直接保存配置，不直接注册 Carbon 热键。非法输入后保持录制状态；所有退出路径都通知设置控制器结束录制会话。

### `SettingsController`

把当前有效快捷键填入录制控件，请求 `AppDelegate` 开始或结束录制态事件桥接，调用快捷键切换事务，并把成功或失败结果反馈到控件。错误采用设置行内提示，不弹出阻塞式系统对话框。

### `AppDelegate`

唯一的运行时热键所有者。负责启动注册、录制态事件桥接、候选注册、配置保存、成功切换和失败回滚。截图动作仍调用现有 `onScreenshotExplain()`，不改变截图与 Azure 调用链。

## 7. 错误反馈与恢复

- 无修饰键的普通按键：显示“请同时按下修饰键和一个按键”，保持焦点并继续录制。
- 只有修饰键：不显示错误，保持焦点并继续录制。
- Carbon 注册失败：显示“无法注册该快捷键，可能已被系统或其他应用占用”，恢复显示当前有效快捷键。
- 配置保存失败：显示“快捷键未保存，原快捷键仍然有效”，注销候选热键并恢复旧值。
- 启动时保存键失效且默认键回退成功：设置页显示默认值，并提供一次非阻塞提示说明已恢复默认。
- 启动时保存键和默认键均不可注册：设置页显示错误状态；用户仍可录制其他组合键。

错误日志只记录键码、修饰键和 Carbon 状态码，不记录 Azure Endpoint、Key、请求正文或其他配置内容。

## 8. 文案与文档同步

所有把 `⌃⌥E` 描述为固定快捷键的用户可见文案必须改为“默认快捷键”或动态读取当前配置，包括基础设置页、屏幕录制权限提示以及 README。源码注释、构建脚本说明、`PROJECTS.md` 和架构文档中的固定快捷键描述同步更新，避免文档再次把可配置值写死。

## 9. 测试与验收

测试必须覆盖以下黑盒行为：

1. 默认配置使用 `⌃⌥E`。
2. 修饰键被标准化，显示顺序稳定为 `⌃⌥⇧⌘` 后接普通键。
3. 无修饰键和只有修饰键的输入被拒绝。
4. 字母、数字、方向键、功能键和常用特殊键可生成稳定显示文本；Escape、Forward Delete 和 Backspace 不可分配。
5. 旧版仅含 Azure 字段的配置解码成功，Azure 内容原样保留，快捷键补为默认值。
6. 新配置编码、保存、重新加载后保持相同键码和修饰键。
7. 候选注册成功并保存后，新快捷键立即触发截图动作，旧快捷键失效。
8. 候选注册失败时，旧快捷键仍可触发，配置文件不变。
9. 配置保存失败时，候选注册被注销，旧快捷键仍可触发。
10. `InstallEventHandler` 失败时热键创建整体失败，不设置已安装标记、不写入 action、不保存候选配置。
11. `RegisterEventHotKey` 失败后 action 表中没有对应残留；`invalidate()` 重复调用保持幂等。
12. 配置保存被阻塞或失败期间按下候选组合键，不会提前执行截图。
13. 旧热键注销失败时，配置回滚与候选注销都被尝试；回滚成功时旧热键继续正常工作且磁盘保持旧值。
14. 配置回写失败但候选注销成功时，本进程只执行旧热键、磁盘保留候选值、修改被锁定，并明确提示重启后的语义。
15. 配置回写和候选注销同时失败时，候选被强引用且保持未激活，只有旧热键执行截图，修改被锁定并提示重启。
16. 候选回滚注销失败时，不产生第二个截图动作或无 action 的僵尸注册；进程退出后由系统释放，重启按磁盘配置重新注册。
17. 在录制器中按当前快捷键进入相同值 no-op，不启动截图，也不让窗口失焦。
18. Escape 取消录制且不调用应用事务入口；带修饰键的 Escape 语义相同。
19. Forward Delete/Backspace 通过同一事务入口恢复默认值；带修饰键时语义相同。
20. 无修饰键的普通输入被拒绝后仍处于录制状态；单独修饰键继续等待且不报错。
21. 设置窗口关闭或录制控件失焦时取消未提交录制，并恢复当前热键的正常截图回调。
22. 应用重启后注册持久化的快捷键。
23. 保存键在启动时不可注册时按规则回退默认键；双重失败时应用仍可进入设置。
24. 现有 Popup、Azure、窗口几何和 Markdown 测试继续通过。

UI 烟测应打开基础设置页，确认录制态、焦点环、快捷键符号、行内错误、说明文字和窄窗口布局没有重叠。最终版本继续使用固定的 `Glint Self Signed` 身份构建 Universal App、安装并验证：

- 固定签名 designated requirement 不变。
- Accessibility 仍为已授权状态。
- 事件 tap 可正常创建。
- 自定义快捷键可拉起框选截图。
- 修改后退出并重新启动 Glint，快捷键仍然有效。

## 10. 非目标

- 不提供快捷键预设下拉列表或手工文本输入框。
- 不支持多个截图快捷键并存。
- 不修改划词监听快捷行为、截图流程、弹窗生命周期或 Azure 请求协议。
- 不检测所有应用的快捷键配置；以 Carbon 实际注册结果作为冲突判定依据。
- 不把快捷键同步到 iCloud、钥匙串或外部服务器。
