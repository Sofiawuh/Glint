# Glint 文字命令面板设计

日期：2026-11-24
状态：已批准，待实施

## 1. 背景与结论

现有“自动检测跨应用文字选区 → 在选区右下角显示小方块 → 悬停后展开”的入口依赖 Accessibility 选区边界、鼠标手势推断和跨应用控件语义。实际使用中，Safari、微信、VS Code、Excel、自绘文本控件和滚动区域返回的 AX 信息并不一致，入口因此会错位、漏触发，也可能把滚动条、Dock 项或普通控件误判为正文选区。

本设计用显式的全局快捷键替换自动入口：用户先在任意应用中选中文字，再按“文字命令快捷键”，Glint 主动读取选中文字，并在当前鼠标右下方直接显示“翻译｜提问”。显式意图消除了对拖选、双击、控件角色、选区边界和悬停时序的猜测。

本设计取代以下入口行为，但不删除其历史文档：

- 自动监听拖选、双击、三击、键盘扩选与 `⌘A`；
- 选区右下角 10×10 pt 小方块；
- 22×22 pt 透明命中区域；
- 悬停 180 ms 后展开；
- 使用 AX 选区 bounds 或鼠标释放点定位入口。

## 2. 用户流程

1. 用户在浏览器、聊天工具、编辑器、邮件客户端或其他应用中选中文字。
2. 用户按“文字命令快捷键”，默认 `⌃⌥T`。
3. Glint 在不激活自身的前提下读取当前选中文字。
4. 读取成功后，在鼠标右下约 12 pt 显示非激活命令面板，直接提供“翻译”和“提问”两个按钮。
5. “翻译”复用现有 Azure Text Translation 请求与结果窗；“提问”复用现有文本上下文、紧凑提问卡片和 Azure OpenAI v1 流式会话。
6. 点击面板外部或按 Escape 关闭面板。
7. 面板显示期间再次按文字命令快捷键时，重新读取当前选中文字，并用新快照替换旧面板。

若没有读取到可用文本，不显示空面板，而是在鼠标旁显示短暂提示：“没有读取到文字，请先选中文字”。

## 3. 快捷键与配置

Glint 保留两套相互独立的全局快捷键：

- 截图快捷键：保留用户当前配置和现有默认行为，不迁移、不覆盖、不重置；
- 文字命令快捷键：新增配置字段，默认 `⌃⌥T`。

两套快捷键都在“设置 → 基础”中独立录制。任何候选快捷键在以下情况下都不得替换当前有效快捷键：

- 与另一套 Glint 快捷键重复；
- Carbon 全局注册失败；
- 配置持久化失败；
- 旧注册注销失败，无法安全完成切换。

录制期间，如果用户按下当前已注册的文字命令快捷键，该按键只回填录制控件，不触发取词或显示面板。旧配置文件缺少新字段时，文字命令快捷键采用默认值，同时完整保留 Azure 配置与截图快捷键。

## 4. 取词与剪贴板事务

文字命令快捷键触发后，Glint 记录源应用并执行以下顺序：

1. 优先从当前 AX 焦点元素及有限父链读取非空 `AXSelectedText`；不要求范围或 bounds。
2. AX 无可用文本时，进入受保护的模拟 `⌘C` 降级。
3. 复制前完整备份剪贴板项目、类型和数据；复制完成后，仅当剪贴板仍由本次事务占有时恢复原内容。
4. 如果复制期间第三方更新了剪贴板，保留第三方的新内容，不用旧备份覆盖。
5. 拒绝空白文本、文件 URL、文件列表、图片和其他非文本对象。

因为用户已经通过快捷键表达明确意图，取词不再检查鼠标移动距离、点击次数、选区 bounds、滚动条角色或旧选区变化。取词在串行后台队列执行；晚到结果通过代际令牌作废，不得覆盖更晚的快捷键请求。

## 5. 命令面板

命令面板为 `NSPanel`：

- `nonactivatingPanel`，不调用 `NSApp.activate` 或 `makeKeyAndOrderFront`；
- 约 168×40 pt，暖纸色表面、深炭文字、赤陶强调，与现有 Glint 视觉语言一致；
- 整个可见按钮区域均可点击，不使用透明扩展命中区；
- 两个文字按钮直接显示“翻译”“提问”，不依赖图标或悬停揭示；
- 按钮具有 hover、按下和键盘焦点反馈，但 hover 不是执行动作的前提；
- 支持 Escape 关闭；外部鼠标按下关闭；
- 保留源应用高亮的最佳努力，不主动夺取焦点。

面板锚点来自 `NSEvent.mouseLocation`，默认位于鼠标右下约 12 pt。布局按鼠标所在显示器的 `visibleFrame` 夹紧，必须正确处理顶部、底部、左右边缘以及负坐标显示器。

无文本提示使用独立、不可交互的短暂面板，位置规则相同，自动消失，且新的快捷键请求会替换旧提示。

## 6. 组件边界

- `TextCommandHotKey` / 快捷键管理：复用现有标准化键值、Carbon 注册、录制和事务切换基础设施；增加双快捷键冲突校验。
- `SelectedTextExtractor`：封装“AX 优先、受保护复制降级、类型过滤、代际作废”，不承担 UI 定位。
- `TextCommandPanelController`：只管理面板呈现、鼠标附近布局、关闭与动作提交；不监听选区变化。
- `AppDelegate`：持有两套快捷键管理器，连接提取器、命令面板与现有 `PopupController`。
- 全局事件 Tap：只保留面板外部点击、Escape、截图或其他仍有明确用途的事件；不再因鼠标释放、移动、双击或普通键盘选择自动取词和显示入口。

## 7. 状态与错误处理

- 每次文字快捷键生成新的请求代际；旧 AX/复制结果自动失效。
- 面板已经显示时，新结果原地替换旧快照并按当前鼠标重新定位。
- AX 权限不足但复制成功时正常工作；AX 与复制都失败时显示无文本提示。
- 快捷键注册或保存失败时，设置页显示可恢复错误，旧有效快捷键继续工作。
- 两套快捷键重复时，在候选生效前拒绝，并提示“不能与另一项快捷键相同”。
- Azure 请求错误继续由现有结果窗和设置探测流程处理，不在命令面板层重复实现。

## 8. 验收标准

- 仅拖选、双击、三击、键盘扩选、`⌘A`、拖滚动条、调整列宽、点击 Dock 或普通点击均不自动显示入口，也不自动复制。
- 在 Chrome、Safari、微信、企业微信、VS Code、TextEdit 等应用中，用户选中文字后按快捷键才发起读取。
- AX 能提供文本时不执行复制；AX 无文本时可通过受保护复制读取纯文本。
- 文件、图片、空白或无选区不显示命令面板。
- 面板直接显示“翻译｜提问”，无小方块和悬停阶段，能被外部点击与 Escape 关闭。
- 四个屏幕边缘和负坐标显示器上，面板完整位于 `visibleFrame` 内。
- 截图快捷键及其用户配置不变；两套快捷键可独立录制且不能重复。
- 现有 Azure Text Translation、Azure OpenAI v1、截图、上下文提问和结果窗功能继续通过完整回归测试。

## 9. 非目标

- 不为 Safari、微信、VS Code 等应用维护应用白名单或专用适配器。
- 不把命令加入各应用原生右键菜单。
- 不引入常驻后台 Python 服务或服务器中转。
- 不恢复自动选区监听、选区 bounds 定位或 hover-only 交互。
