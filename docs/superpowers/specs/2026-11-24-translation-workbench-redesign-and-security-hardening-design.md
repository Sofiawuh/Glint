# Glint 翻译工作台重设计与安全加固

日期：2026-11-24  
状态：用户已批准开发  
影响范围：翻译工作台、Azure 凭据持久化、文本浮窗稳定性、AI 长文本与请求生命周期

## 1. 目标

本发布批次同时完成以下工作：

1. 将翻译工作台升级为用户批准的“方案 A：精密双卡片”，消除短文本的大面积空白和灰度过低、动作同权的问题；
2. 保留并强化“复制全部”，同时复制当前原文与译文的纯文本和 RTF；
3. 将 Azure Translator、Azure OpenAI、Azure Speech 的 API Key 从明文 JSON 迁移到 macOS Keychain；
4. 移除私有 CGS API，避免系统升级与审核风险；
5. 消除 `NSScreen.screens[0]` 的空数组越界路径；
6. 关闭上一轮独立终审发现的四个 P1：AI 请求身份竞态、润色事实保护盲区、Translator 超长单段、AI 人工分批边界泄漏。

所有改动必须保留当前 Azure-only 架构、默认翻译不调用 GPT、最近 10 条结果仅进程内保存和 Universal Binary `arm64 + x86_64` 约束。

## 2. 翻译工作台：精密双卡片

### 2.1 窗口与视觉方向

- 保留 Glint 轻量、可钉住、可缩放的浮窗，不改成标准主应用窗口；
- 右上角钉住动作必须使用明确的图钉图形：未钉住为 `pin`，已钉住为 `pin.fill`，不得使用准星或定位符号；
- 使用上下双卡片：上方原文、下方译文；每张卡片有清晰边框、标题栏、语言状态、编辑区和字数信息；
- 采用现有 Glint 暖白纸张与陶土强调色，但正文、按钮和边界提高对比度；
- 不使用紫蓝 AI 渐变、低对比灰字或大面积装饰性留白；
- 浏览器设计预览中的 `Connected` 属于预览工具状态，不是 Glint 产品元素，正式 UI 不得出现；
- 原文与译文卡片完全对等，均可编辑、滚动、单侧排版、单侧润色、朗读和复制。

### 2.2 自适应密度

- 短文本打开时使用紧凑首选高度，不再强制两个巨大等高画布；
- 两个编辑区仍保留可点击、可编辑的安全最小高度；
- 长文本在各自 `NSScrollView` 中独立滚动，窗口继续允许用户手动放大；
- 用户手动调整后的尺寸继续按现有规则保存，程序不得在用户操作过程中反复跳动；
- 内容变化只影响新打开时的建议高度，不以动画不断重排当前窗口。

### 2.3 卡片标题栏

原文卡片标题栏：

- `原文`；
- 自动识别到的语言；
- `排版`、`润色`、`朗读`、`复制`。

译文卡片标题栏：

- `译文`；
- 目标语言选择器；
- `排版`、`润色`、`朗读`、`复制`。

所有图标或紧凑按钮必须有可见提示和 `accessibilityLabel`，支持键盘焦点。目标语言变化只保存选择并提示重新翻译，不自动产生网络请求。

### 2.4 底部控制栏

底部按以下层级排列：

1. 左侧：处理中指示和简短状态；
2. 右侧翻译动作：`重新翻译`；
3. 右侧 AI 模式：`智能排版`或`智能润色`；
4. 右侧当前 AI 动作：`一键智能排版`或`一键智能润色`。

`复制全部`不占用底栏：它以双页复制图标固定放在窗口右上角的图钉与关闭按钮之间，tooltip 和 accessibility label 均为“复制全部”。

`严格保留`隐藏或禁用一键 AI。初次翻译和重新翻译继续只调用 Translator。

动作权重随状态变化：

- Translator 译文与当前原文一致时，一键 AI 是强调动作；
- 用户编辑原文后，工作台进入“译文可能过期”状态，`重新翻译`成为强调动作；
- 译文过期时不得启动双侧一键 AI，单侧编辑和单侧 AI 仍按各自契约处理；
- 网络和 AI 失败不得覆盖现有内容。

### 2.5 复制全部

右上角的`复制全部`在普通工作台和最近结果只读工作台中始终可用，只要任一侧有内容。

复制内容按以下顺序生成：

```text
原文
<当前原文编辑器内容>

译文
<当前译文编辑器内容>
```

- 纯文本保留当前段落、空行、列表和签名结构，不包含界面装饰标签；
- RTF 保留当前结构化报告的标题、重点、段落、列表和签名视觉；
- 复制的是当前编辑器真实内容，包括用户修改或 AI 排版后的结果；
- 成功后按钮短暂显示“已复制”，不弹阻塞窗口；
- 最近结果只读状态隐藏编辑、排版、润色和重新翻译，但保留朗读、单侧复制和复制全部。

## 3. Azure Keychain 凭据架构

### 3.1 存储边界

以下三项只存入 macOS Keychain Generic Password：

- Azure Translator API Key；
- Azure OpenAI API Key；
- Azure Speech API Key。

Keychain service 使用稳定的 Glint 专用标识，三个 account 使用稳定、互不冲突的服务名。Keychain 项目使用仅本机可用的安全可访问级别，不输出到日志、错误、文档或测试产物。

`config.json` 只保留 Endpoint、Region、Deployment Name、Vision、快捷键和翻译偏好等非敏感项。编码后的 JSON 中不得出现 Azure `apiKey` 字段或 Key 值。

### 3.2 启动迁移

启动读取按以下顺序执行：

1. 解码现有 JSON 的非敏感配置，并暂存旧版明文 Azure Key；
2. 读取 Keychain 中已有的三个 Key；
3. Keychain 已有值时，以 Keychain 为准；
4. Keychain 无值且旧 JSON 有值时，将旧值写入 Keychain；
5. 三项迁移全部成功后，原子重写 `config.json`，删除敏感字段，并将文件权限设为 `0600`；
6. 同时净化 `config.pre-azure-backup.json` 中的敏感字段/值并设为 `0600`；
7. 任一必要 Keychain 写入失败时，不提前删除对应旧明文，保留可重试状态并返回不含密钥的错误；
8. 迁移幂等，多次启动不重复创建冲突项，不用旧 JSON 覆盖更新后的 Keychain 值。

若旧备份包含已下线 Provider 的 `apiKey`，必须先安全迁移到专用 legacy Keychain account 或保留原文件，不得在未保存凭据时直接删除。最终发布验收要求默认配置与备份均不再包含明文 Key。

### 3.3 保存事务

设置页保存 Azure 配置时：

1. 先将三个 Key 的新值写入、更新或删除 Keychain；
2. Keychain 操作成功后再原子写入无 Key 的 JSON；
3. JSON 写入失败时回滚内存状态，并尽最大努力恢复此前 Keychain 值；
4. 任一步失败，设置页不得显示“保存成功”；
5. 测试连接继续使用表单当前输入，不要求先保存。

配置目录权限使用 `0700`，`config.json`、`config.pre-azure-backup.json` 和其他可能包含历史凭据的配置文件使用 `0600`。

### 3.4 可测试边界

Keychain 访问通过协议注入：生产实现使用 Security.framework，测试使用进程内虚构存储。测试不得访问用户真实 Keychain 或 `~/.config/glint`。

## 4. 公共 API 与屏幕安全

### 4.1 移除私有 CGS API

删除所有 `_CGSDefaultConnection`、`CGSSetConnectionProperty`、`dlopen`、`dlsym` 和 `unsafeBitCast` 私有调用。

I-Beam 光标只依赖公开 AppKit 能力：

- `NSTrackingArea` 使用 `.activeAlways` 和 `.cursorUpdate`；
- `cursorUpdate`、`mouseMoved`、`mouseEntered` 按真实字形命中调用 `NSCursor.iBeam.set()`；
- 离开文字或窗口时恢复 `NSCursor.arrow`；
- 公共 API 无法在某个系统过渡状态更新光标时安全降级为箭头，不得崩溃或调用私有符号。

### 4.2 空屏幕列表

任何代码不得使用未检查的 `NSScreen.screens[0]`。

屏幕选择规则：

1. 优先包含鼠标点的屏幕；
2. 否则选择距离鼠标点最近的屏幕；
3. 否则使用 `NSScreen.main`；
4. 屏幕列表和主屏均不可用时，使用以当前鼠标点为中心的有限安全矩形计算面板位置；
5. UI smoke 在无屏幕过渡态不得越界，无法截图时返回失败结果而不是崩溃。

屏幕选择和 fallback 几何应提取为纯值函数，以便不依赖真实显示器测试。

## 5. 上一轮终审 P1

### 5.1 AI 请求身份

主控增加不可复用的 `TranslationAIRequestIdentity`。只有当前 identity 与领域 generation 都匹配时，回调才允许：

- 清除 task handle；
- 写回工作台状态；
- 更新编辑器或状态栏；
- 显示错误。

历史切换、停止工作、新 AI 请求、编辑导致取消和重新翻译都必须让旧 identity 失效；单侧和双侧 generation 同时正确失效。

### 5.2 润色保护

- 保护中文“姓名 + 是 + 角色”句式；
- 列表顺序校验使用每项相对其他项的区分性事实锚点，不能只比较共享通用词；
- 不再把所有英文句首 TitleCase 单词视为实体；
- `Customers → Clients` 等普通同义改写允许通过；
- 人名替换与 production/staging 列表交换必须拒绝。

### 5.3 Translator 超长单段

单个超过 45,000 字符的 fragment 必须稳定拆分为多个可请求 fragment，每批字符数和项目数均满足 Azure 预算，响应后按拆分元数据无损重组，不得误报“Azure 配置错误”。

### 5.4 AI 人工分批边界

长段因预算硬拆时记录人工连接边界。重组模型区块时：

- 原始段落边界保留 `\n\n`；
- 人工切点直接拼接，不新增空行；
- 单侧和双侧处理均使用同一重组规则；
- 智能排版仍执行字符忠实校验，润色仍执行事实保护校验。

## 6. 错误、日志与隐私

- 日志不得输出 Key、Keychain item data、真实正文、剪贴板正文或完整错误响应中的敏感字段；
- Keychain 错误只报告服务名和通用状态；
- JSON 迁移失败保留原文件并报告可恢复状态；
- AI、Translator、Speech 继续使用现有脱敏器；
- UI smoke 使用独立临时配置目录和虚构 Keychain 存储，不读取真实凭据。

## 7. 测试与验收

实现前由全新独立测试代理创建红灯契约。至少覆盖：

- JSON 编码不包含 Azure Key 字段或值；
- 三服务旧明文 Key 成功迁移到虚构 Keychain 后清理当前配置和备份；
- Keychain 写失败时旧明文不被清除；
- 迁移幂等，Keychain 现有值优先；
- 配置文件权限 `0600`，配置目录 `0700`；
- 设置保存的 Keychain/JSON 事务与失败回滚；
- 生产源码不包含私有 CGS 符号与动态解析；
- 屏幕数组为空时的纯几何 fallback；
- 双卡片布局、短文本紧凑建议高度、长文本滚动能力；
- 普通与只读状态的复制全部；
- RTF/纯文本复制当前编辑器结构；
- 源文变脏后的动作权重和双侧 AI 准入；
- 上一轮四组 P1 精确反例；
- Translator、GPT、Speech、快捷键、选区读取、最近结果和既有工作台回归；
- `arm64-apple-macos12.0` 与 `x86_64-apple-macos12.0` 全源码 typecheck；
- 固定签名 Universal App 构建、隔离 UI smoke、安装版签名和进程路径；
- 最终独立只读终审必须为 `APPROVE / P0=0 / P1=0 / P2=0`。

## 8. 发布

验收完成后：

1. 使用 `Glint Self Signed` 构建并替换 `/Applications/Glint.app`；
2. 重启并验证安装版进程；
3. 提交当前功能分支并推送；
4. 创建 GitHub PR；
5. 通过 merge commit 合并 `main`，不 squash、不 rebase；
6. 保留功能分支；
7. 核对远端 `main` 与本机安装版本来自同一最终提交。
