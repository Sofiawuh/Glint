# 结果窗口图钉与恢复设计

## 1. 问题

Glint 当前在检测到用户点击结果窗口外部时调用 `dismiss()`，同时销毁窗口、划选上下文和追问会话。用户感知为窗口“自动收起”，但实际上没有保留状态，也没有重新打开上次窗口的入口。

## 2. 目标

- 用户可将当前结果或追问窗口钉住，避免外部点击导致窗口消失。
- 未钉住的窗口在外部点击时只隐藏，不销毁内容。
- 隐藏后的窗口可从菜单栏 Glint 菜单恢复。
- 只有明确关闭操作才销毁上下文和会话。
- 会话只保存在当前进程内存中，不写入磁盘。

## 3. 交互设计

### 3.1 图钉按钮

- 在展开的翻译结果、问答结果和多轮追问窗口右上角增加图钉按钮，位于复制按钮左侧。
- 未钉住时显示灰色线性图钉，提示文字为“钉住窗口”。
- 钉住时图标使用 Glint 赤陶强调色并显示选中状态，提示文字为“取消钉住”。
- 快捷划词胶囊不显示图钉；只有展开内容窗口支持钉住。
- 图钉状态只作用于当前窗口，不持久化为全局偏好；创建新会话时默认未钉住。

### 3.2 外部点击

- 当前窗口已钉住：点击其他 App 或窗口空白处时保持显示，不改变会话。
- 当前窗口未钉住：外部点击时执行“隐藏并保留”，停止显示但不清除窗口内容、上下文、追问记录或当前生成结果。
- 流式回答期间隐藏窗口时，请求继续进行；恢复后显示已经累积的最新内容。

### 3.3 恢复入口

- Glint 菜单栏菜单增加“显示上次窗口”。
- 仅当存在已隐藏且可恢复的内容窗口时启用该菜单项；没有可恢复窗口时置灰。
- 恢复后窗口回到隐藏前的位置和尺寸，并显示隐藏期间产生的最新流式内容。
- 如果窗口本来就在屏幕上，菜单项保持置灰，避免重复激活。

### 3.4 明确关闭

- 点击右上角 `×`：取消在途请求，销毁窗口、上下文和追问记录。
- 在输入框中按 Escape：保持现有语义，视为明确关闭并销毁会话。
- 退出 Glint：内存中的隐藏或钉住会话全部清除。

### 3.5 新划词行为

Glint 保持单窗口、单会话模型：

- 存在钉住窗口时，新的文字划选不替换该窗口，也不弹出新的快捷胶囊；用户需要先取消钉住或关闭当前窗口。
- 存在未钉住但已隐藏的上次窗口时，新的有效划选会销毁旧隐藏会话并显示新快捷胶囊。
- 存在未钉住且可见的窗口时，新划选沿用现有单窗口行为，替换为新划词快捷胶囊。

该规则避免为了图钉引入多窗口管理，同时保证“钉住”不会被后台划词事件意外覆盖。

## 4. 状态与边界

窗口控制器需要区分：

- `visible`：当前显示。
- `hiddenRestorable`：已隐藏、状态保留、菜单可恢复。
- `dismissed`：已销毁、不可恢复。

图钉是可见内容窗口的独立布尔状态。快捷胶囊不进入可恢复状态；它在外部点击时仍可直接关闭，以免短暂划词提示长期占用内存。

隐藏操作不得调用现有的完整 `dismiss()`。完整关闭继续负责递增 generation、取消请求、清理引用和执行淡出动画。恢复操作只负责重新显示已有 `NSPanel`，不重新创建请求或重复追加消息。

## 5. 测试与验收

必须覆盖以下状态转换：

1. 未钉住内容窗口外部点击后进入 `hiddenRestorable`，上下文和会话仍存在。
2. 菜单“显示上次窗口”恢复同一窗口、位置、尺寸和内容。
3. 钉住窗口外部点击后仍为 `visible`。
4. 钉住窗口不会被新划词替换。
5. 未钉住的隐藏窗口可被新划词替换。
6. `×` 和 Escape 进入 `dismissed`，取消请求且菜单恢复项不可用。
7. 隐藏期间流式内容继续累积，恢复后可见。
8. 快捷划词胶囊保持原有轻量关闭行为。
9. 原有 Azure、几何、Markdown 与设置测试继续通过。

UI 验收应确认图钉与复制、关闭按钮的间距、悬停状态、选中颜色、工具提示以及窄窗口下不重叠。应用继续使用固定的 `Glint Self Signed` 身份构建和安装。

## 6. 非目标

- 不支持同时保留多个结果窗口。
- 不把会话历史写入配置文件或本地数据库。
- 不跨 Glint 重启恢复窗口。
- 不让钉住窗口自动跨 macOS Space 或覆盖全屏应用。
