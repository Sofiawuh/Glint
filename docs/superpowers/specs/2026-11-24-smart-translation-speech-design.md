# Glint 智能翻译与 Azure Speech 设计

日期：2026-11-24  
状态：已实施

## 1. 目标

将现有单一译文浮窗升级为可编辑的翻译工作台，并解决长邮件、网页、PDF、列表和表格等文本翻译后换行及结构被压成一排的问题。

本次同时增加 Azure Speech 朗读能力：Azure 设置中提供独立的 Speech Endpoint、Key 和连接探测；当前翻译的原文与译文分别可一键朗读。

## 2. 配置

### 2.1 基础设置

新增“翻译”配置：

- 目标语言模式：
  - `自动识别`（默认）：源语言为中文时译为英语，其余源语言译为简体中文；
  - `固定目标语言`：用户从受支持语言列表中选择目标语言。
- 智能排版：
  - `智能排版`（默认）：修复硬换行并识别段落、标题、列表、引用、邮件头、签名、代码和简单表格；
  - `严格保留`：只规范换行编码与尾随空格，不合并或重构行。

配置必须向后兼容：旧配置缺少新字段时使用上述默认值，不覆盖现有 Translator、Azure OpenAI 和快捷键配置。
基础页的目标语言与排版偏好在选择后立即事务保存；写入失败时恢复原值并提示，不依赖切换到 Azure 页再点保存。

### 2.2 Azure 设置

新增 Azure Speech 配置组：

- Speech Endpoint：接受完整的 Azure Speech TTS REST 地址；
- Speech Key：安全输入，不写日志；
- Speech Voice：默认 `自动匹配语言`，允许使用自动映射的神经语音；
- `测试连接`：使用不包含用户内容的固定短文本发起真实最小合成请求，验证 Endpoint、Key 和语音是否可用。

Translator、Azure OpenAI 与 Speech 三组配置独立探测，并通过同一个保存动作事务落盘；任一字段保存失败时整体回滚，避免内存配置与磁盘配置不一致。

## 3. 智能排版模型

### 3.1 原则

- 智能排版同时应用于原文和译文；
- 内部保留未经排版的原始文本用于回退，但默认显示和编辑排版后的文本；
- 只调整文字结构，不改写词义、数字、金额、日期、URL、邮箱、路径、变量名或代码；
- 不使用 GPT 重写或整理，避免额外费用与语义漂移；
- 无法可靠恢复源应用的字体、颜色、图片、分页或复杂 HTML 布局。

### 3.2 区块

格式化器将输入解析为稳定区块：

- 普通段落；
- 标题；
- 项目符号与编号列表；
- 引用；
- 邮件头；
- 签名或分隔线；
- 代码块；
- 管道或 Tab 分隔的简单表格；
- 空行。

智能模式合并普通段落内的视觉硬换行，同时保留结构区块和空行。严格保留模式不重构区块。

### 3.3 翻译

- 可翻译区块拆分为独立片段批量发送给 Azure Translator；
- 列表标记、编号、表格分隔符、代码和结构边界不进入翻译正文；
- Translator 返回片段后按稳定 ID 原位重组；
- Azure 自动检测源语言，响应中的检测结果用于显示源语言并决定自动目标语言；
- 自动目标模式首次请求使用本地兼容判断选择目标，响应检测结果用于窗口语言标签与后续重译；
- 单批遵守 Azure 条目和字符预算，超限时按区块边界分批，不截断用户正文。

## 4. 翻译工作台

结果窗口由上下两个编辑区组成：

1. 原文：显示智能排版后的原文，可编辑；
2. 译文：显示重组并排版后的译文，可编辑。

窗口顶部显示 `源语言 → 目标语言`，右上保留图钉与关闭。每个编辑区分别提供：

- 朗读 / 停止；
- 复制。

底部提供：

- 当前排版模式；
- 目标语言选择；
- `重新翻译`。

重新翻译始终读取当前原文编辑区内容，重新排版并覆盖译文；修改译文不会自动请求 Azure。

请求在途时禁用重新翻译、语言切换和最近结果切换，但不清空用户编辑内容。过期或已取消回调不得覆盖更新后的编辑区。

## 5. 复制

原文、译文和“复制全部”均复制当前编辑区的最终内容，而不是原始抓取字符串。

剪贴板同时写入：

- `public.utf8-plain-text`：保留排版后的段落、换行、编号、缩进和表格字符；
- RTF：保留标题、列表缩进、段落间距、引用和等宽代码样式。

目标应用自行选择支持的格式。复制操作不记录正文日志。

## 6. Azure Speech

- 原文按钮朗读当前原文编辑区内容；
- 译文按钮朗读当前译文编辑区内容；
- 朗读前移除内部排版标记，但保留自然停顿所需的段落；
- 使用语言代码自动选择 Azure Neural Voice；
- 同一时间只有一个播放器，开始另一段时停止上一段；
- 再次点击当前朗读按钮立即停止；
- 音频仅保存在内存，不写入磁盘或最近结果；
- 请求代际用于丢弃晚到音频，窗口关闭时取消请求并停止播放；
- Speech 未配置或请求失败时显示脱敏错误，不影响编辑、复制和重新翻译。

## 7. 最近结果

- 成功翻译后记录当前排版后的原文与译文；
- 重新翻译成功时更新同一条翻译记录，不重复占名额；
- 历史窗口继续只读，不提供重新翻译或云端朗读入口；
- 退出 Glint 后历史仍全部清空。

## 8. 隐私与日志

- Translator、Azure OpenAI 和 Speech Key 只写入本机配置；
- 日志不得包含 Key、Endpoint 查询参数、原文、译文、朗读正文、剪贴板正文或音频数据；
- UI smoke 必须使用独立 `GLINT_CONFIG_DIR`，不得读取真实配置；
- 测试使用明显虚构的 Endpoint、Key 和文本样本，不访问用户剪贴板或网络。

## 9. 验收

- 自动/固定目标语言保存、迁移和请求路由正确；
- 原文与译文均智能排版并可编辑；
- 邮件、PDF 硬换行、列表、引用、代码和简单表格保持可读结构；
- 复制输出排版后的纯文本与 RTF；
- 修改原文后可重新翻译，修改译文后可复制和朗读；
- Azure Speech 配置、真实探测、原文朗读、译文朗读、停止和错误恢复可用；
- 既有提问、截图、快捷键、最近结果和 Azure 配置不回归；
- Universal Binary、固定签名、本机安装和隔离 UI smoke 全部通过。
