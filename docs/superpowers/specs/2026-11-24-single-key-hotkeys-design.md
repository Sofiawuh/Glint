# Glint 安全单键快捷键设计

日期：2026-11-24  
状态：已确认，待实施

## 1. 目标

Glint 的文字命令快捷键支持单键触发，并将键盘数字 `1` 左侧的物理键 `` ` / ~ `` 设为新默认值。同时避免普通字母、数字和常用标点被注册为无修饰键的全局热键，从而破坏微信、浏览器、VS Code 等应用中的正常输入。

本设计只调整快捷键值、录制校验、旧默认迁移和设置页反馈；不改变文字取词、翻译、提问、截图、Azure 配置或浮窗流程。

## 2. 有效快捷键规则

无需修饰键即可保存的按键只有：

- 数字 `1` 左侧的物理按键 `` ` / ~ ``，Carbon key code 为 `kVK_ANSI_Grave`；
- `F1` 至 `F20` 功能键。

其他按键必须至少包含一个受支持的修饰键：

- Control；
- Option；
- Shift；
- Command。

以下输入继续无效：

- 单独的普通字母、数字、方向键、空格、回车、Tab、数字键盘键或其他标点；
- 单独按物理修饰键；
- `Escape`、`Delete` 和向前删除键作为快捷键值。

`Escape` 在录制期间仍用于取消，`Delete` 或向前删除键仍用于恢复对应功能的默认快捷键。

## 3. 默认值与迁移

- 文字命令的新默认快捷键为单独的 `` ` ``，即 `kVK_ANSI_Grave` 且 modifiers 为 `0`。
- 截图快捷键的源码默认值仍为 `⌃⌥E`。
- 用户当前已保存的截图快捷键不迁移、不覆盖；例如已有 `⌃⇧Q` 时继续保留。
- 旧配置缺少文字命令字段时，直接使用新默认 `` ` ``。
- 已保存文字命令值恰好等于旧默认 `⌃⌥T` 时，在加载配置时迁移为新默认 `` ` `` 并持久化。
- 已保存为其他有效自定义值时原样保留，不因本次升级覆盖。
- 已保存的异常或无效值继续通过现有启动回退流程恢复到新默认。

迁移只比较规范化后的 key code 与 Carbon modifier bits，不读取或修改 Azure Endpoint、Key、Region、部署名称及其他配置。

## 4. 双快捷键与注册事务

文字命令与截图录制器采用相同的有效值规则，因此两者都可使用单独的 `` ` `` 或 `F1–F20`。现有双快捷键约束继续生效：

- 两套快捷键不得相同；
- 候选值先以未激活状态注册；
- 注册、配置保存或旧快捷键注销失败时，旧有效快捷键继续工作；
- 录制期间按当前已注册快捷键只回填录制器，不触发文字命令或截图。

Carbon 注册必须按候选值原样传递 `modifiers = 0`，不能自动补入修饰键。

## 5. 设置页交互

录制控件的主交互不改变：点击控件后直接按目标按键。

录制态提示改为：

> 请按快捷键…

当用户单独按下不允许的普通键时，录制保持进行，不保存候选值，并在当前录制器下方显示内联错误：

> 可单独按 ` 或 F1–F20；其他按键需搭配修饰键

该错误紧邻对应录制器显示，并通过现有状态标签向辅助功能暴露；不能只依赖红色边框或颜色表达错误。用户随后输入有效值、取消录制、切换设置页或关闭设置窗口时，错误清除。

文字命令帮助文案同步显示新默认 `` ` ``；截图帮助文案继续显示截图默认值。两个录制器都应正确展示单键值，不额外显示修饰符占位。

## 6. 已知行为

当文字命令使用单独的 `` ` `` 作为全局热键时，直接按反引号会触发 Glint，而不会作为普通反引号输入目标应用。这是用户明确选择的全局单键行为。

`Shift + 反引号键` 是不同的组合键，不等同于默认的无修饰键候选；macOS 顶排功能键是否需要同时按 `Fn`，由系统“将 F1、F2 等键用作标准功能键”的设置和键盘硬件决定。

## 7. 测试与验收

由全新测试上下文先补黑盒测试并确认红灯，至少覆盖：

- 单独的 `` ` `` 有效，显示文本为 `` ` ``；
- 单独的 `F1`、`F12`、`F20` 有效；
- 单独的字母、数字、方向键、空格、回车、Tab、普通标点和数字键盘键无效；
- 上述普通键加入任一受支持修饰键后仍按既有规则有效；
- `Escape`、删除键和物理修饰键行为不回归；
- 新默认是无修饰键的 `kVK_ANSI_Grave`；
- 缺失文字命令字段采用新默认；
- 已保存旧默认 `⌃⌥T` 自动迁移，其他自定义值与截图键保持不变；
- 两套快捷键对相同单键继续执行冲突保护；
- 注册、保存和注销失败继续保留旧有效快捷键；
- 设置页错误文案、清除时机和 UI smoke test 正确。
