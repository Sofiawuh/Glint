# Glint 智能排版可靠性与长文工作台实施计划

日期：2026-11-24  
状态：实施中  
对应规格：`docs/superpowers/specs/2026-11-24-ai-formatting-reliability-and-long-document-layout-design.md`

## 1. 独立契约测试红灯

1. 由全新上下文的独立测试 Agent 只依据已批准规格编写黑盒契约，不参考后续实现。
2. 扩展 Azure GPT 协议契约，覆盖纯 JSON、代码围栏、前后说明、字符串内括号与转义引号、原译文结构不一致，以及未知字段继续拒绝。
3. 扩展结构化渲染契约，覆盖无标记 `key_points` 不新增正文字符、已有标记原样保留、纯文本和 RTF 字符一致。
4. 扩展工作台展示契约，覆盖短文紧凑、长文 760pt 目标高度、正常屏幕下两个正文区均不低于 240pt，以及两个独立滚动区。
5. 先运行定向测试并保存预期红灯证据。

## 2. AI 响应与结构校验

1. 在 `TranslationAIService` 中实现字符串状态感知的首个完整 JSON 对象提取：追踪字符串、转义、花括号深度，忽略 JSON 外前缀、后缀和代码围栏。
2. 保留顶层键、区块类型和字段白名单；继续拒绝模型生成的颜色、字体、HTML、CSS 和未知字段。
3. 移除原文与译文区块数量、类型和重点项数量必须匹配的限制；两侧分别合法且非空即可。
4. 保持现有单次 Azure 请求、分批与取消代际，不增加第二次常规 GPT 请求。
5. 细化解析失败与内容保护失败的 UI 文案，不记录正文或凭据。

## 3. 无损结构化渲染

1. 修改 `TranslationBlockRenderer`：`key_points` 不再为无标记项目补 `•`，视觉强调仅通过段落属性、背景和边线呈现。
2. 已有项目符号或编号原样保留，纯文本、富文本字符串和复制内容保持同一字符序列。
3. 继续使用 `TranslationContentValidator` 的智能排版字符忠实校验和智能润色事实保护；不通过时保留 Translator 成功结果。
4. 运行协议、渲染、校验和分批契约至绿灯。

## 4. 长文工作台布局

1. 将短文/长文分类提取为可测试的公开纯值策略，沿用 1,600 字符和 14 行阈值。
2. 短文继续使用约 430pt 紧凑高度；长文使用 760pt 目标高度，并由主控制器限制在屏幕可用高度减 24pt 内。
3. 长文视图中每个正文滚动区优先获得至少 240pt；屏幕不足时降低优先级并继续保持两侧独立滚动，不越界。
4. 保存尺寸只能放大或保持长文目标，不得把长文首次展示压回 570pt 浅条状态。
5. 运行 AppKit 展示契约，并用虚构长邮件执行本地视觉 smoke。

## 5. 全量验收与发布

1. 运行所有相关 Swift 契约测试、全量测试、双架构类型检查和 `git diff --check`。
2. 独立只读终审确认无 P0/P1/P2 回归后再提交业务实现。
3. 更新 CHANGELOG 和必要的架构/运行文档，不改变 Azure-only、Keychain 和手动触发边界。
4. 构建 `arm64 + x86_64` Universal App 与 DMG，使用 `Glint Self Signed` 签名。
5. 备份当前 `/Applications/Glint.app`，停止旧进程，替换安装并重启。
6. 验证 Bundle ID、签名、架构、进程、短文/长文工作台和智能排版核心链路。
7. 推送功能分支、创建 GitHub PR，以 merge commit 合并 `main`；不 squash、不 rebase并保留功能分支。
