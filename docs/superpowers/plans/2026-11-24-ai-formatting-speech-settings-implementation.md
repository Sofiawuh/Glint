# Glint AI 排版、润色与 Speech 设置实施计划

日期：2026-11-24
状态：已完成

## 1. 契约测试红灯

1. 由全新上下文的独立测试 Agent 仅依据已确认规格编写黑盒契约测试，不参考后续实现。
2. 新增或扩展测试覆盖：
   - `严格保留 / 智能排版 / 智能润色` 三种处理模式与旧配置迁移；
   - 标准邮件段落、Unicode 项目符号、空行和签名不被压平；
   - Azure GPT 非流式结构化区块请求、严格 JSON 解析、未知区块拒绝；
   - 智能排版字符忠实校验与智能润色事实保护；
   - 结构化报告纯文本与 RTF 渲染；
   - 翻译工作台单一目标语言 / 文本处理入口与最后选择持久化；
   - Speech Portal Endpoint 转 TTS Endpoint、仅 Endpoint + Key、自动 Voice 与旧配置迁移。
3. 使用虚构 Endpoint、Key 和正文运行新增测试，确认在实现前按预期失败。

## 2. 领域模型与 Azure 协议

1. 扩展文本处理模式为 `strict / smart / polish`，保持旧 `smart / strict` 配置兼容。
2. 修复基础格式器：优先保留已有换行，识别 `• / ◦ / ▪ / ‣ / –` 等 Unicode 列表，不再主动合并不确定段落。
3. 新增结构化区块模型、规范纯文本重组器、字符忠实验证器和润色保护项验证器。
4. 新增 Azure GPT 非流式 AI 后处理服务：
   - 一次请求同时处理原文和 Translator 译文；
   - 系统提示词限制白名单区块与模式边界；
   - 严格解析 `source_blocks / translation_blocks`；
   - 失败、超时、取消、过期或校验失败不覆盖当前内容。
5. 将 Translator 与 AI 后处理拆分为两次显式操作：初次翻译和重新翻译不调用 GPT；一键处理只读取当前原文与译文，失败时两侧都不覆盖。

## 3. 结构化报告与工作台

1. 将翻译编辑区升级为可编辑富文本，并实现固定“结构化报告”样式：
   - 正文阅读行距和段间距；
   - 重点清单浅色强调、左侧色条与列表缩进；
   - 标题、小节、引用、代码、表格和签名层级；
   - 不可变编号、金额与日期的轻量强调。
2. 原文和译文使用对应区块顺序；界面装饰不进入规范纯文本。
3. 纯文本复制保留文字、段落和列表；RTF 复制保留结构化报告视觉。
4. 基础设置删除翻译目标和文本排版。
5. 翻译工作台底部成为唯一入口：
   - 目标语言：自动识别或具体语言；
   - 文本处理：严格保留、智能排版、智能润色；
   - 选择立即持久化，重新翻译时生效。
6. 增加原文 / 译文手动智能排版和智能润色操作，使用请求代际阻止晚到覆盖。
7. 底部增加随当前模式变化的“一键智能排版 / 一键智能润色”；严格保留时隐藏，处理期间显示稳定进度与状态。
8. “复制全部”使用右上角双页图标，位于图钉与关闭之间；底栏不再重复放置按钮，卡片内单侧复制保持不变。

## 4. Speech 设置与迁移

1. Azure 设置页 Speech 组只保留 Endpoint、API Key 和测试连接。
2. 接受 Portal 通用 Endpoint 与标准 TTS Endpoint，从主机名解析 Region 并生成实际 TTS URL。
3. Voice 始终按朗读语言自动选择，不显示用户设置。
4. 迁移旧 Endpoint 和 Voice，不修改或输出 Key。
5. 改进字段校验和连接错误，确保无效输入指出 Endpoint、Key 或区域问题。

## 5. 回归、文档与发布

1. 更新 `PROJECTS.md`、架构概览、README、构建运行手册和 CHANGELOG。
2. 运行新增契约测试、全部既有 Swift 测试、双架构类型检查和隔离配置 UI smoke。
3. 使用固定签名构建 Universal Binary、`Glint.app` 和 DMG。
4. 备份现有安装，停止旧进程，替换 `/Applications/Glint.app` 并重新打开。
5. 验证安装版签名、进程、Speech 设置布局、翻译工作台模式与结构化报告 smoke。
6. 独立只读终审必须达到 `APPROVE` 且 `P0=0 / P1=0 / P2=0`。
7. 推送功能分支，创建 GitHub PR，以 merge commit 合并 `main`；不 squash、不 rebase，保留功能分支。
