# Glint 最近结果历史实施计划

日期：2026-11-24  
对应设计：[2026-11-24-recent-results-history-design.md](../specs/2026-11-24-recent-results-history-design.md)

## 阶段 1：测试契约与红灯

由全新上下文的独立测试代理先添加黑盒契约测试，覆盖：

- 翻译与已完成文字问答生成历史快照，加载中、失败、取消、未发送草稿和截图会话不进入历史；
- 最近 10 条与 10 MB 纯文本预算，超限时淘汰最旧条目，单条超限时拒绝入库；
- 同一文字问答会话的新回答更新原条目，不重复新增；
- 菜单标题按更新时间倒序，包含时间、类型和安全截断摘要，空状态与清空动作正确；
- 历史 ID 路由只生成只读内容，不创建输入框、发送按钮或 Azure 请求；
- 浏览历史不丢失当前空闲会话或未发送草稿，“显示当前窗口”可切回；
- 在途网络请求期间不可切换历史；关闭、Escape、外部点击仅隐藏历史，不删除记录；
- 日志和菜单契约不泄露选中文字、问题、回答、配置或凭据。

主代理运行新增测试并确认其因缺少最近结果能力而准确失败，记录红灯后才修改生产代码。

## 阶段 2：纯内存领域层

1. 新增 `RecentResults.swift`，定义不依赖 AppKit 和网络层的 `RecentResultEntry`、结果类型、只读快照和 `RecentResultStore`。
2. 实现按 ID 更新、倒序读取、最多 10 条、10 MB UTF-8 文本预算、最旧淘汰、查找和清空。
3. 新增菜单展示模型与摘要生成：仅输出时间、结果类型和截断后的单行标题；正文不进入日志。
4. 将领域文件加入 Universal Binary 构建清单，不读取或持久化用户配置。

## 阶段 3：结果采集与会话边界

1. 翻译请求只在当前 generation 的最终成功回调中写入完整译文快照。
2. 文字提问会话分配稳定的历史 ID；每轮流式回答正常完成后，把已完成 transcript 更新到同一条记录。
3. 截图提问、错误、取消、过期回调和未发送草稿不写入历史。
4. 记录写入和菜单刷新统一在主线程完成；历史正文不写入日志。

## 阶段 4：菜单与只读窗口

1. 将“显示上次窗口”改为“显示当前窗口”，保留当前隐藏窗口或草稿恢复能力。
2. 新增始终存在的“最近结果”子菜单：空状态、最近 10 条、清空动作及在途请求禁用状态。
3. 点击历史时保存当前空闲会话 UI 快照，并用唯一内容窗口展示只读翻译或问答结果；不构建输入框和发送按钮。
4. 关闭历史只改变其可见状态；再次选择可重建。选择“显示当前窗口”时重建并恢复原会话、草稿、窗口大小与状态。
5. 增加隔离 Home 的 UI smoke test，验证菜单、切换、只读控件、清空和当前窗口恢复。

## 阶段 5：文档与回归

1. 更新 `PROJECTS.md`、`docs/architecture/overview.md`、README 和 CHANGELOG 的当前能力描述。
2. 运行全部 Swift 契约测试、Python 静态/集成测试、`git diff --check` 和敏感信息扫描。
3. 分别对 `arm64-apple-macos12.0` 与 `x86_64-apple-macos12.0` 类型检查。
4. 使用固定身份 `Glint Self Signed` 构建 Universal Binary、App 和 DMG。
5. 安全备份并替换 `/Applications/Glint.app`，验证签名、双架构、进程重启和隔离 Home UI smoke test。

## 阶段 6：复审与 GitHub 交付

1. 由独立只读复审代理检查差异和测试证据；达到 `APPROVE / P0=0 / P1=0 / P2=0` 后提交功能代码。
2. 推送功能分支并创建 PR，将 PR 附加到当前任务。
3. 用 merge commit 合并到 `main`，不 squash、不 rebase、不删除功能分支。
4. 本地 `main` fast-forward 到远端最终提交，更新 Obsidian 项目事实、增量清单和任务日志。
